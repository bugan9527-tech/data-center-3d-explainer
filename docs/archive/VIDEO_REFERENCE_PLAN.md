## 第一阶段：把已有功能放进一个完整的工程展品（已完成）

### 场景

- 保持一个小型机房和约八台机柜的范围，明确系统区域及人员通道。
- 网络柜体现交换机端口与配线；计算柜体现服务器托盘；存储柜体现磁盘或存储模块。
- 保留 UPS、配电和制冷设备，增加可辨认的接线或风道，让位置关系帮助解释职责。
- 使用有控制的金属、塑料和玻璃材质；优先改善边缘、接触阴影和光照，避免只堆叠几何数量。

### 界面

- 桌面以大面积三维工作区为主体，约占主内容宽度的四分之三作为初始设计目标。
- 将常驻的左右说明区改为精简系统导航与可展开的职责面板；窄屏使用下方说明或抽屉。
- 顶部保留整体结构、工作分工、协作流程；底部用清晰的系统章节和播放控制组织内容。
- 只显示当前对象需要的说明，保持字号、键盘选择与文字替代入口。

### 镜头

- 建立机房总览、网络区、计算区、存储区、供电区、制冷区六个预设视角。
- 初期在现有机房画布与内部画布间使用推近、淡入衔接；内部资产预加载完成后再切换。
- 返回时保留用户原来的视角与选择。
- 所有过渡可中断；用户手动旋转后暂停自动导览；减少动态效果时直接定位。

验收：从总览进入一个系统，再进入服务器内部并返回，用户能保持空间方位；模型有明确的外形差异；现有内部选择和播放功能保持可用。

## 第二阶段：让各系统的工作能被直接观察

- 网络：请求从入口进入，指定端口与转发路径依次高亮。
- 计算：延用已完成的网卡、CPU、内存协作动画，将它与机房级流程衔接。
- 存储：读写请求、控制单元和存储模块按逻辑阶段高亮；不用机械转动泛指所有存储介质。
- 供电：展示上游、UPS、配电柜、母线、机柜 PDU 与设备电源的示例功能关系（已完成，见 `SUPPORT_VALIDATION.md`）。
- 制冷：用风扇与简洁气流说明送风、吸热和回风；标明气流为原理示意（已完成）。
- 两者都以独立章节分步讲解，不插入请求步骤，并可与业务流程同看。
- 监测：展示传感器采集状态并送往汇集节点的关系。

每次突出一条主要工作路径，其他内容保留空间背景。数据、电力和气流的颜色、箭头与图例保持统一。
参与本步与用户当前选择应分别表达，避免用户把选中状态当成运行状态。

验收：用户能通过模型、路径和文字说明，讲出各系统的职责、连接对象与输出。

## 第三阶段：提供可自由浏览的完整导览

建议一个约 35 秒的导览脚本，时长可在试用后调整：

1. 0–5 秒：机房全景，说明六类系统组成。
2. 5–10 秒：网络区，展示请求进入和转发。
3. 10–18 秒：计算机柜与服务器内部，展示网卡、CPU、内存分工。
4. 18–24 秒：存储区，展示数据读取和返回。
5. 24–30 秒：供电与制冷的持续支撑。
6. 30–35 秒：回到全景，汇总系统协作关系。

用户可以播放、暂停、切换章节或退出导览。镜头、部件高亮、路径与讲解共用同一进度，暂停时同步保持。
配音和字幕可在文字讲解与交互验收后增加。
