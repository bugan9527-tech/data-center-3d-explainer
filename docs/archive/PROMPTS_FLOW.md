# 提示词流程手册

给想照着这个项目做**另一个题材**（计算机组成原理、操作系统、网络协议、机械装配……）的人的提示词写法。不追求细节完备，只给"先说什么、后说什么"的顺序，和每段话的验收标准。

思路只有一句：**先把讲解数据写出来，再让 AI 去建三维**。题材换了，流程不变。

---

## 一、先花五分钟定住项目

先把这五句填完，后面所有提示词都从它派生。

| 要回答 | 数据中心项目当时的答案 | 计算机组成的答案（示例） |
| --- | --- | --- |
| 讲什么 | 一次"读取并处理云端文件"的请求怎么穿过机房 | 一条指令怎么在 CPU 里走完六个阶段 |
| 给谁看 | 不熟悉机房结构的学习者 | 学过数字逻辑、没看过真实芯片结构的学生 |
| 主体形态 | 一个可旋转的机房沙盘 | 一块可拆的主板 + 可钻进去的 CPU 内核 |
| 一次讲多久 | 11 个步骤，每步 4 秒 | 取指→译码→取数→执行→访存→写回，6 步 |
| 明确不做 | 不做故障排查、不做 CFD、不做真实接口 | 不做电路时序仿真、不做流水线冲突分析、不做真实指令集 |

最后一行最重要。**"不做什么"写得越具体，返工越少。**

---

## 二、六个阶段，六段提示词

每段话都是一次完整交付，发完等结果，看过验收再发下一段。不要一次贴两段。

### P1 · 骨架：先让它能跑（半天）

目的不是好看，是让后面每一步都有地方落。

```
新项目 <目录>：一个用三维讲清 <主题> 的教学展品。技术栈 Vite + React + react-three-fiber + three.js，
不引入其他运行时依赖。

这一轮只做骨架：
1) 一个全屏画布，深色背景，一块地面，相机可拖动旋转、滚轮缩放。
2) 一个占位立方体放在原点，代表主体。
3) 页面标题与一句副标题，其余界面都先不做。
4) 静止时按需渲染，不要常驻 requestAnimationFrame 空转。

验收：npm run dev 能打开；拖动/缩放正常；控制台 0 error；build 通过。
```

> 这一步别让 AI 顺手写业务。骨架越干净，后面越不容易推倒重来。

### P2 · 数据先行：先把话说清楚（一天）

**这是全流程里最关键的一步。** 先把"讲什么"写成纯 JS 数据，界面和三维都还没有也能读通。

```
在 src/data/ 下建立三个文件，只写数据，不写任何三维组件：

1) systems.js：<N> 个部件/系统，每个含 id、名称、一句话职责、接收什么、输出什么、和谁配合。
2) flow.js：主流程分 <6> 个阶段，每阶段含标题、当前由谁在工作、用到的节点 id 列表、
   路径（按节点 id 顺序）、两句话讲解。
3) layout.js：每个部件在场景里的位置（世界坐标）与占用尺寸。

文案要求：写"负责什么、接收什么、输出什么、和谁配合"，不写性能数字、不写实现细节。
先把这三个文件当一篇说明文来写，写不通就说明还没想清楚，先别做三维。
```

> 验收：把这三个文件读一遍，能不看图就讲明白原理，比如"取指时 PC 把地址送上地址总线，主存把指令送回指令寄存器"。讲不通就改文案，不要靠模型补救。

### P3 · 模型：先能区分，再谈好看（两三天）

部件之间**必须有结构差异**，否则用户分不清谁是谁。

```
按 src/data/layout.js 的位置，把每个部件做成三维对象：

1) 优先用代码拼几何（盒子、圆柱、面板），够用就别开 Blender；
2) 需要精细外观的（机柜、芯片封装、主板）用 Blender 脚本生成，脚本要能一键重跑，
   导出 GLB 到 public/models/，源文件放 blender/source/；
3) 每个可拆解的部件独立命名（如 part_alu、part_regfile、part_cache），
   原点放在自身几何中心，方便后面沿轴拉开；
4) 同类部件共用几何与材质（克隆而不是重复创建）。

验收：build 通过；每个部件能被单独点中（不同颜色临时标一下也行）；
GLB 有节点统计脚本输出，节点名符合 part_* 契约。
```

### P4 · 动效：一条时间轴管全部（两三天）

项目里所有"动"的东西——阶段推进、路径流动、拆解、脉冲——都由**一个播放时钟**驱动。这条做了，暂停一致性、跨步、后台暂停全都免费得到。

```
加一条统一的播放时钟（hooks/useWorkflow.js），只有一个 progress 与 step，
所有动画都从它派生，不允许组件自己读 Date/performance。

1) 每个阶段高亮它的节点，并画出该阶段的路径（曲线 + 方向箭头 + 沿线移动的光点）；
2) 不同性质的流用不同颜色（示例：控制流 蓝、数据流 紫、地址 青）；
3) 播放条：播放/暂停/重播 + 可点的分步进度；
4) 暂停时画面必须完全静止（截图两次像素一致）；
5) 系统开启"减少动态效果"时，只保留静态箭头，不生成移动光点与循环。
```

> 验收就一条：**暂停后连拍两张截图，必须一模一样。** 这条不过，后面所有性能优化都是白做。

### P5 · 界面：让文字跟着选中走（一两天）

```
右侧（或右下）加说明面板：选中部件时显示职责、输入、输出、与谁配合、当前阶段在做什么。
顶部加标题与状态条，底部放播放条。

规则：
1) 面板里的所有读数（频率、命中率、温度、吞吐）都必须标注"模拟"，不得声称接入真实数据；
2) 窄屏（375 宽）改为单列堆叠，不出现横向滚动；
3) 键盘可完成主要操作（Tab 选、Enter 触发、Esc 退出）；
4) 点设备只改选中，不自动甩镜头；镜头只能由明确按钮触发。
```

### P6 · 收口：让"改坏了"能被立刻发现（一天）

```
1) 在三维画布与面板上挂诊断属性：data-camera（相机位姿）、data-flow（当前阶段/进度）、
   data-panel（面板状态），字段一旦定下不许改名；
2) 写浏览器回归脚本（Playwright）：阶段推进、暂停冻结、点选部件、拆解、窄屏无溢出、
   控制台 0 error，约 20–40 项；
3) 用 npm script 一条命令跑完全部，输出 JSON 与截图；
4) README 写清：跑什么命令、已实现什么、明确不做什么。
```

> 诊断属性是这套方法的核心资产。界面怎么改都行，只要 `data-*` 契约不变，回归就一直有效。

## 三、换题材只改三处

| 要改的 | 在哪 | 数据中心 → 计算机组成 |
| --- | --- | --- |
| 节点与阶段 | `src/data/*.js` | 机房设备 → CPU 内部部件；11 阶段请求 → 6 阶段指令执行 |
| 资产与坐标 | `layout.js` + Blender 脚本 | 机柜/CRAC/UPS → 芯片封装/ALU/寄存器堆/Cache/主存/总线 |
| 文案口径 | 各 data 文件的 role/input/output | "负责什么、接收什么、输出什么"结构完全照搬 |

代码结构、动效时钟、面板、回归脚本**一行都不用改**。

**题材映射参考**

| 本项目 | 计算机组成原理对应 |
| --- | --- |
| 网络 → 计算 → 存储的请求路径 | 取指 → 译码 → 执行 → 访存 → 写回 |
| 供电/制冷"持续支撑" | 时钟与电源：不占主流程，但始终在跑 |
| 机柜拆解看内部件 | 芯片开盖看 ALU / 寄存器堆 / Cache |
| 机柜 PDU、母线 | 片上总线、地址/数据/控制三组线 |
| 备份与容灾（独立柜） | Cache 层级（L1/L2/主存）分层存放的对比 |

---

## 四、四句话原则

1. **一次只发一段。** 一次贴两段，AI 会跳过验收。
2. **约束写不变式，不写步骤。** "暂停必须冻结""不改步骤划分"比"第 3 步先改 A 再改 B"管用。
3. **验收只认证据。** build 结果、截图路径、回归项数，三样缺一样就当没过。
4. **不许改测试迁就实现。** 否则回归脚本两轮之后就失去意义。

## 五、第一段可以直接粘的话

朋友如果连第一步都不想自己想，把这段发过去就行（把 `<...>` 换掉）：

```
帮我从零做一个三维教学展品，主题是 <计算机组成原理：一条指令如何执行>，
受众是 <学过数字逻辑、没看过真实芯片结构的学生>。

技术栈：Vite + React 19 + react-three-fiber + three.js，不引入其他运行时依赖。

这一轮只做骨架，不做业务：
1) 全屏画布、深色背景、一块地面、相机可拖动旋转与滚轮缩放；
2) 原点放一个占位立方体代表主板；
3) 页面只有一个标题和一句副标题；
4) 静止时按需渲染，不要空转。

做完告诉我：怎么启动、改了哪些文件、有没有控制台报错。
先不要写讲解内容、不要建模型、不要做界面，等我确认骨架之后再继续。
```

确认骨架能跑，再发 P2（数据先行）。**顺序别调**——先做模型再想文案，最后一定返工。
