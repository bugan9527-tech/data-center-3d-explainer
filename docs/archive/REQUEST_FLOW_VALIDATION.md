# 网络、计算与存储请求：实施与验证

日期：2026-10-30。基于已有工程增量开发，保留沉浸布局、六个章节镜头、机柜及内部展示、进入／返回衔接，没有新增运行时依赖。所有新截图来自真实运行页面。

## 本轮实现

唯一业务为“用户读取并处理一份云端文件”。业务固定运行在 N01、C01 的 01 号服务器与 S01，其他机柜保留为空间背景并可单独观察。

| 阶段 | 当前工作 | 主要方向 |
| --- | --- | --- |
| 1 | 接收外部请求 | 用户 → A 外网端口组 |
| 2 | 交换单元选择出口 | A → 转发单元 → B |
| 3 | 请求到达服务器网卡 | B → C01 |
| 4 | CPU 执行程序，内存保存工作数据 | C01 内部原理，可按需进入 |
| 5 | 计算服务器发出读取请求，控制单元接收 | C01 → B → 转发单元 → C → S01 控制单元 |
| 6 | 控制单元定位文件所在模块 | 控制单元 → 文件模块 |
| 7 | 模块读出持久保存的数据 | 文件模块 → 控制单元 |
| 8 | 文件数据返回计算服务器，读入内存 | 控制单元 → C → 转发单元 → B → C01 |
| 9 | CPU 处理内存数据并整理结果 | C01 内部原理，可按需进入 |
| 10 | 服务器网卡发送响应，网络转发 | C01 → B → 转发单元 → A |
| 11 | 用户收到结果 | A → 用户 |

A 固定连接外网，B 固定连接 C01，C 固定连接 S01。组内插口数量经过教学简化，同一组可双向工作；返回时 B 接收、A 输出，不再把“入口／出口”误当作端口的永久方向。示例不模拟真实协议、寻址、排队或传输时延。

每一步提供“发生什么、哪个部分负责、接收什么、输出到哪里”和完整文字方向。蓝色表示请求、紫色表示文件数据、绿色表示处理结果；两级共用图例。一次只突出当前主要业务路径，电力和冷空气开关仍可显示持续支撑关系，不插入请求顺序。

网络模型保留三个独立端口组和转发单元；存储模型保留控制单元和本次文件模块。当前功能组使用金色描边与局部发光，选择使用蓝框与勾选，场景与文字设备列表均可操作。普通设备选择与定位不改变业务进度；点击功能节点会显示该节点的具体职责。

## 状态与层级

- `requestFlow.js` 是机房流程阶段、拓扑、节点锚点、职责与内部映射的唯一配置；旧的五步机房流程已移除。
- `useWorkflow.js` 为机房与内部共用的播放时钟。阶段变更、移动标记与结束状态都读取同一份阶段内累计时间；暂停不清零，继续使用剩余时间。
- 手动选步会暂停并定位到该阶段起点；重新开始回到第一步并暂停；结束后保持最后一步和终点，只有再次主动播放才重启。
- 页面隐藏时暂停；回到前台不自动继续。减少动态效果时仍可播放文字阶段，模型保留静态箭头并停止移动标记。
- 进入内部时冻结机房进度，按对应原理阶段打开内部；内部可独立观察五阶段，不推进机房请求。返回恢复机房阶段、分数进度、设备选择、镜头和入口焦点，等待用户继续。
- C02–C04 仍可进入，其界面明确说明业务示例运行于 C01，当前柜展示相同教学结构。

小画布隐藏空间浮动标注，保留实体高亮、静态箭头和文字列表；桌面标注用引线避开主要功能节点。选中蓝框及引线不参与拾取，避免遮挡实际端口点击。

合计 **203 项**。关键验证包括：

- 完整播放 11 阶段直至用户收到结果，标记停在用户端，等待后不循环；每阶段方向、主要设备、真实模型功能组材质、端口和存储模块高亮与说明对应。
- 暂停后等待超过单步时长，阶段和分数进度不变，两次实际画布 PNG 内容完全相同；继续后使用暂停前剩余时间推进。
- 最后一步中途暂停再继续不会回到第一步；重新开始和任意选步均清除上一阶段金色高亮，保留独立的蓝色用户选择。
- 普通系统选择、观察供电设备和文字节点选择不改变业务进度；播放时选择设备仍继续播放。真实 A 端口及文件模块网格可点击。
- 展开存储柜后路径端点跟随功能装配移动；进入内部从对应 CPU 原理阶段开始，内部选步后返回仍保留机房原来的阶段和分数进度。
- 原有六镜头定位、快速切换、手动打断、职责面板、加载取消、进入返回、CPU 网格点击、内部展开及键盘操作通过。
- 机房覆盖 375×812、768×1024、1024×768、1440×900、812×375；内部覆盖前四种尺寸。没有横向溢出，窄屏空间标注隐藏，主要按钮可操作。
- 减少动态效果下保留静态箭头，播放时两次画布截图相同。演示结束稳定后 500 ms 内检测到的 requestAnimationFrame 回调为 0。
- 无 WebGL 时仍能选机房文件模块、阅读输入输出、选步、播放／暂停，并进入内部文字说明和返回；内部界面资源失败仍保留机房和取消入口。故障注入页的预期初始化错误与正常交互分开记录。

后台暂停验证：无头 Chrome 的额外标签页没有将原页变为 hidden，因此本次明确使用 `document.hidden=true` 与 `visibilitychange` 平台事件注入，检查暂停、时间冻结和回到前台不自动续播。此项验证了处理逻辑，尚未人工复核有界面浏览器最小化、操作系统锁屏或移动浏览器后台挂起。

## 复现与剩余限制

```powershell
npm.cmd run build
npm.cmd run preview
# 使用终端实际地址，首次运行需要已安装的 playwright-cli 和 Chrome
npm.cmd run verify:browser -- -Url http://127.0.0.1:4174/
python scripts/inspect-assets.py
```

- 本轮只完整实现读取，不增加写入流程；端口、地址、介质和连接为教学简化，不模拟协议时序、电路波形、DMA、操作系统调度或磁盘机械动作。
- 计算阶段在机房中用服务器前面板局部框和逻辑回路示意；CPU、内存与网卡细节由内部按需观察，不制作完整自动镜头导览。
- 示例固定一个文件模块和三台参与机柜，不扩展为任意业务拓扑、真实设备接口、故障排查、维修或实时监控。
- 原有 `THREE.Clock` 弃用警告与约 1028 kB 公共三维包超过 500 kB 的构建提示仍存在，未屏蔽警告或升级无关依赖。
- 未完成目标硬件长期性能基准、完整屏幕阅读器认证、有界面浏览器后台人工复核及所有移动设备兼容性验证。
