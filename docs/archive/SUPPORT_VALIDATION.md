# 供电与制冷工作表现：实施与验证

日期：2026-10-30。本轮在已有沉浸界面、六个章节镜头、11 阶段请求流程和服务器内部演示之上，补齐供电与制冷的正常工作表现。没有新增运行时依赖，所有截图来自真实运行页面。

## 本轮目标与边界

- 说明每个部分负责什么、电力与空气经过哪些设备、它们如何持续支撑网络、计算与存储。
- 只讲正常工作原理：不模拟电网故障、UPS 切换、电池充放电时序、真实 CFD、温度场或制冷功率计算。
- 供电与制冷不插入请求的 11 个顺序步骤，而是作为持续支撑单独讲解，并可与业务流程同时查看。
- 简化架构在界面和文档中标注，不宣称对应某座真实机房。

## 供电系统

### 教学链路

上游电源引入 → UPS → 配电柜 → 机房配电母线 → 机柜 PDU → 设备电源模块。

| 步骤 | 当前设备 | 接收什么 | 输出到哪里 |
| --- | --- | --- | --- |
| 1 电源引入 | 上游电源引入箱（后墙） | 外部电网的交流电 | UPS 输入端 |
| 2 UPS 稳压 | UPS 不间断电源 | 上游交流电 | 稳定连续的交流电 |
| 3 配电分路 | 配电柜 | UPS 输出 | 多条带保护的回路 |
| 4 母线下送 | 机房配电母线 | 配电柜回路 | 各机柜上方的分支电力 |
| 5 机柜 PDU | C01 机柜 PDU（机柜侧面） | 机柜回路 | 各设备插座的回路 |
| 6 设备电源 | C01 的服务器电源模块 | 机柜 PDU 的交流电 | 设备内部直流电 |

- 琥珀色路径、方向箭头和单个移动标记表示供电关系与逻辑方向；标记速度不代表真实电流速度，也不绘制电路波形。
- 每个节点都可在三维场景（点击设备本体或空间标注）或文字节点列表中选择，右侧面板给出“负责什么、接收什么、输出到哪里、与谁配合”。
- UPS、配电柜使用原有特写；机柜 PDU 与设备电源共用“机柜正面”机位。所有镜头只能通过“查看本步特写”按钮触发。
- 其他机柜仍由母线取电，用较细的分支线表示，不重复讲解每个机柜的 PDU。

## 制冷系统

### 机房布局调整

为了让进风与排风关系自洽，后排机柜（N02、C03、C04）旋转 180°，与前排机柜背靠背布置：

- 两排机柜的背面相对，形成中间的**热通道**；正面分别朝向两个**冷通道**。
- 冷通道地面铺送风地板（前排 5 块、后排 3 块，与机柜列对齐）。
- 制冷设备位于后墙，前部上部为回风格栅与风扇、中部为盘管、下部为送风开口。
- 请求流程仍只使用 N01、C01、S01（前排），11 阶段节点锚点未改变。

### 教学回路

制冷设备热交换 → 架空地板送风层 → 地板送风口 → 设备风扇 → 空气经过部件吸热 → 排风侧 → 回风返回制冷设备。

| 步骤 | 当前设备 | 接收什么 | 输出到哪里 |
| --- | --- | --- | --- |
| 1 热交换 | 制冷设备 | 较热回风 | 降温后的冷空气 |
| 2 地板送风 | 架空地板送风层 | 制冷设备冷空气 | 各送风口 |
| 3 送风口 | 地板送风口 | 静压层冷空气 | 冷通道 |
| 4 设备风扇 | 机柜风扇模块 | 冷通道空气 | 设备内部 |
| 5 空气吸热 | 服务器内部部件 | 冷空气 | 较热空气（颜色由青转暖） |
| 6 排风离开 | 机柜排风侧 | 吸热后的空气 | 热通道 |
| 7 回风返回 | 机房回风路径 | 热通道上升空气 | 制冷设备 |

- 青色表示冷空气，暖色表示吸热后的回风，图例在讲解面板中常驻。
- 制冷设备风扇与服务器风扇模块在播放时转动；面板明确说明“风扇负责推动空气，制冷设备负责热交换”。
- 路径与标记是工作原理示意，不是流体仿真。静压层内的送风路径画在地板表面以便观察，文字注明它代表地板下方的送风层。

## 分步讲解与播放状态

供电 6 步、制冷 7 步各自使用独立的播放时钟（`useWorkflow`），与请求流程共用同一套实现：

- 播放、暂停、继续、重新开始、手动选步；手动选步暂停并回到该步起点；重新开始回到第一步并暂停；结束保持最后一步，不自动循环。
- 暂停保留阶段与动画位置：标记与风扇停在当前帧，两次画布截图完全一致；继续从暂停进度恢复。
- 页面切到后台时，三个演示（请求、供电、制冷）一起自动暂停；回到前台不自动续播。
- 减少动态效果时保留静态路径、箭头和文字，停止移动标记与风扇。

## 三种展示方式

1. 单独观察供电：进入“持续支撑”，供电章节默认只打开电力路径。
2. 单独观察制冷：切到制冷章节，电力路径自动关闭，只保留冷空气与回风。
3. 在业务流程中同时查看：“在协作流程中同时查看”切换到 11 阶段流程并保留支撑图层；也可在流程页用“电力／冷空气”按钮叠加。同时显示时请求路径为主，支撑路径降为较细、较低透明度，并在阶段说明下方显示“持续支撑（不属于请求步骤）”的支持链摘要与“单独观察”入口。

三种状态在视觉上分开表达：

| 状态 | 表达 |
| --- | --- |
| 用户选中的设备 | 蓝色选择框与 ✓ 勾选、面板“已选择的设备” |
| 当前讲解强调的设备 | 节点描边（供电琥珀／制冷青或暖色）+“参与本步” |
| 持续提供支撑的设备 | 文字列表中的“持续支撑”标记与面板说明 |

## 镜头与界面

- 保留原有 UPS 与配电、制冷设备两个章节镜头，其余四个章节不变。
- 11 个机位覆盖供电 6 个、制冷 7 个共 13 个功能节点（排风与回风共用热通道机位）：6 个原有特写（电源引入、UPS、配电柜、制冷设备、送风口、设备内部气流）+ 5 个机内／功能机位。其中母线→母线仰视、机柜 PDU／设备电源→机柜正面、地板送风层→地板低角、设备风扇→冷通道、回风→热通道。
- 特写只在点击“查看本步特写”时触发；普通选择与文字节点选择不移动镜头；镜头过渡仍可被拖动、滚轮和新的定位中断；减少动态效果时直接定位。
- 支撑模式隐藏其他系统的空间标注，只保留本章节相关标注与节点标注，减少视觉干扰。
- 浅色工程风格、字号与按钮尺寸沿用现有约定；窄屏下步骤改为三列、说明单列，空间标注隐藏，文字列表完整可操作。

## 状态与层级

- `src/data/supportSystems.js` 是供电与制冷的节点、步骤、路径、镜头和文案的唯一配置。
- `src/scene/SupportVisualization.jsx` 负责基础路径、当前步骤路径、箭头、移动标记与节点框；`src/scene/Infrastructure.jsx` 负责设备模型、母线、送风地板与风扇旋转。
- `useWorkflow.js` 未修改，三个演示共用同一实现，避免出现多套互相矛盾的控制逻辑。
- 进入服务器内部时暂停全部演示，内部仍从对应原理阶段独立开始；返回后保留机房模式、支撑章节、步骤、图层、选择与镜头，不自动重启。
- 三维画布的 `data-support` 暴露当前章节、步骤、进度、活动节点与图层，供回归脚本读取真实状态。

## 复现与剩余限制

```powershell
npm.cmd run build
npm.cmd run preview
# 使用终端实际地址
npm.cmd run verify:browser -- -Url http://127.0.0.1:4180/
python scripts/inspect-assets.py
```

- 供电与制冷是教学简化：不模拟电网故障、UPS 切换、电池充放电时序、双路电源、配电保护整定、风量平衡、CFD、温度场或制冷量计算。
- 后半排机柜旋转 180° 是为了让进风／排风方向与箭头一致；实际机房的行列布置、封闭通道与送回风形式会因设计而不同。
- 静压层送风路径画在地板表面以便观察；路径不绘制地板下方的风道截面。
- 只展示 C01 的机柜 PDU 与设备电源细节，其余机柜只画母线分支，不重复讲解每柜接线。
- 未完成目标硬件的长期帧率、显存与长时间运行基准；未做完整屏幕阅读器认证与真机移动端复核。
- 原有 `THREE.Clock` 弃用警告与公共三维包超过 500 kB 的构建提示仍存在，未屏蔽警告或升级无关依赖。
