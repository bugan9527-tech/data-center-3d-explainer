# 视觉与镜头优化方案

日期：2026-10-31。依据：参考视频 `C:\Users\PC\Desktop\3D智慧农业场景_7700134417188080934.mp4`（26 秒，已抽帧到 `work/video-reference/`），以及当前工程的实际实现。

目标：在**不改动教学结构、11 阶段请求流程、供电 6 步／制冷 7 步内容与全部交互约定**的前提下，让页面从“等轴测示意图”变成参考视频那种“能走进去的展品”。

## 一、参考视频的四条画面规律

| 观察 | 帧 | 对应问题 |
| --- | --- | --- |
| 相机走进场景：低机位、广角透视，轨道与管线形成引导线 | 04、07 | 现有 6 个章节镜头全部是外部 3/4 正交俯视，没有一个在场景内部 |
| 场景是“带收边的沙盘”，地面向雾里淡出，没有硬边房间盒子 | 01 | 现在是 12×9 白地板 + 两面浅灰墙，右前有一大片空地板 |
| 强主光、长影子、室内暗背景亮，靠明暗差建立纵深 | 07、09 | ambient 1.2 + hemi 1.1 把阴影冲平，画面发灰 |
| 叠加层是边角玻璃卡 + 左下大章节号，主体占画面 90% | 07、09 | 左栏 + 右白面板 + 底部白卡三块常驻，场景被挤在中间 |

## 二、阶段与内容

### 阶段 A：镜头体系（收益最大）

**A1 正交改透视。** 现在 `Canvas` 使用正交相机，`RoomCameraRig.fit()` 用 `width/height` 求 `camera.zoom`。正交投影没有近大远小，这是“模型感”的根因。改为单一透视相机：

- 每个机位增加 `fov`；总览用长焦（fov ≈ 14、距离拉远）模拟近正交，章节与特写用 fov 32–45。
- 取景计算改为“由 `width` 与 `fov` 求相机距离”，`data-camera` 继续暴露 `position / target / zoomRatio`，`zoomRatio` 改为归一化取景系数，保持现有回归断言可用。
- 相机交互、可中断过渡、减少动态效果直接定位、进入/返回视角恢复全部保持不变。

涉及：`src/scene/RoomCameraRig.jsx`、`src/scene/DataCenterViewport.jsx`（Canvas 相机参数）、`src/data/roomCameras.js`。

**A2 新增机内与功能机位。** 六个章节镜头不动，新增可由按钮触发的视角：

| 机位 | 位置 → 目标 | 用途 |
| --- | --- | --- |
| 冷通道 | 视高 1.55，沿 x 向纵深看 | 制冷第 4 步（设备风扇进风侧） |
| 热通道 | 视高 1.7，位于两排机柜之间 | 制冷第 6、7 步（排风 → 回风） |
| 机柜正面 | 距 C01 正面 1.4，正视 | 供电第 5、6 步（机柜 PDU → 电源模块） |
| 母线仰视 | 从地面仰看 y=2.86 的母线 | 供电第 4 步 |
| 地板低角 | 视高 0.5，沿送风主干 | 制冷第 2 步（地板送风层） |

最终落地：11 个机位覆盖供电 6 个、制冷 7 个共 13 个功能节点（6 个原有特写 + 5 个机内／功能机位；排风与回风共用热通道机位），步骤 1/3/5 仍用原有特写。

**A3 过渡更像运镜。** 现有过渡是 0.85 秒直线插值。改为：时长可配置（章节 1.2 秒、特写 0.9 秒）、位置沿轻微弧线（中点抬升 8% 后回落）、缓入缓出；仍可被拖动、滚轮、新定位中断；减少动态效果直接定位。

**A4（可选）步伐微移。** 播放时相机绕目标做 ≤1.5° 的缓慢推移，角度由当前步骤进度驱动，因此暂停即冻结、换步即归零，不写入 `cameraSnapshot`；用户一旦手动旋转即停止，直到下次定位。此项单独开关，若影响“暂停画布一致”的回归则退回 A3 的弧线过渡。

### 阶段 B：光照、材质与背景

- 主光降至 2.7 并收紧 shadow camera（±8），ambient 1.2→0.55，hemi 1.1→0.5，加一盏冷色轮廓光（0.9）。
- 开启 ACESFilmic 色调映射，曝光 1.02，让金属高光不过曝、暗部不糊。
- 背景从平涂 `#eaf0f4` 改为画布透明 + CSS 垂直渐变，并在场景内加轻雾（0.012），远端自然淡出。
- 地板改为径向 alpha 淡出（运行时生成 64×64 径向贴图，不引入外部素材），四周不再出现硬切边。
- 复核：琥珀 `#c58b18`、青色 `#1296b8`、暖色 `#c1743a`、请求蓝 `#2468df` 在新光照下仍可区分；节点高亮的 emissive 强度按新环境重调。

涉及：`src/scene/DataCenterViewport.jsx`、`src/scene/Infrastructure.jsx`、`src/styles/global.css`。

### 阶段 C：沙盘基座与构图

- 地板下沿加深色收边（plinth），与地板同轮廓、内收 0.1、下沉 0.12，形成“展品台”。**不得外扩**：外扩会越过 S2 建立的地板淡出带，重新带出一条矩形硬边；基座复用同一张世界坐标衰减贴图，band 取 6–7（约 1.1 世界单位）。
- 右前空地补齐：备件柜、托盘、检修推车、地面通道标线、冷/热通道地贴（“冷通道 A”“热通道”，窄屏隐藏文字）。
- 总览取景收紧（width 16.8→15.2、目标略右移），消除右前大片空地板。
- 删除 `Floor` 里 y≈-0.63 的 8 条地脚支腿，由基座接管“托住地板”的语义。
- **基座不作为可看见的“台”**：地板完成径向淡出后，基座唯一能露出的位置是顶板遮住的中央区，做成“核内实心、到边再淡”与顶板自身的衰减等价，只是多一层重复几何。S3 实测认为不可见即删除，改为对墙面做 Y 向淡出（见 S4b），这才是当前画面里最硬的边。
- 淡出带内任何新几何都共用同一张世界坐标衰减贴图，道具不允许一半踩在带上。
- 复核：新增道具不得遮挡请求锚点，`data-flow-pick-projections` 的 A 端口与文件模块仍可点中。

### 阶段 D：流光路径

- 当前步骤增加“发光头 + 短尾迹”：头部为加性混合的径向 sprite（运行时生成 32×32 贴图），尾迹取曲线末端 12% 分三段递减透明度。
- 静态路径保持现有细线与半透明箭头；箭头缩小、降低不透明度，避免与流光抢注意力。
- 限制：同屏最多 2 条流光，只在当前步骤渲染；暂停时随进度冻结，减少动态效果时不生成。

涉及：`src/scene/SupportVisualization.jsx`、`src/scene/RequestVisualization.jsx`。

### 阶段 E：展品叠加层（新增“展品模式”）

- 顶部新增开关；开启后：隐藏左侧系统栏，右侧说明收成右下玻璃浮层，左下显示大号章节序号与标题（`04 供电` / `05 制冷`，以 `systems.js` 的 index 为准），底部保留细进度条。
- 内容仍只来自现有数据（步骤、职责、输入输出），**不引入任何虚构数值或仪表盘**。
- 关闭后恢复现有三栏布局；键盘焦点顺序、`aria` 与窄屏单列行为保持。

涉及：`src/App.jsx`、`src/components/SupportPanel.jsx`、`src/styles/global.css`。

**S9 落地结果（2026-11-01）。**

- 顶部 `header-meta`（与“示例架构”同区）新增“展品模式”开关，默认关闭，`aria-pressed` 反映状态；只存 React state，不写 localStorage 或 URL。

- 左下大号章节号：持续支撑取章节对应系统的 `index`（供电 **04**、制冷 **05**，与方案示例的“03”不同，以 `systems.js` 数据为准）；工作分工取当前系统的 `index` 与名称；整体结构/协作流程没有对应系统编号，只显示标题。
- 底部展品条：供电 6 段 / 制冷 7 段 / 请求流程 11 段，每段是可点击、可 Enter 触发的步骤按钮（只表达离散索引，不做逐帧进度）；旁边是播放/暂停与“第 X / N 步”。整体结构与工作分工无播放，不显示进度条。

### 阶段 F：自动导览（独立立项）

8–10 个镜头节拍、约 40 秒：总览 → 供电（进线→母线→机柜 PDU）→ 制冷（制冷设备→送风口→回风）→ 请求流程收尾 → 回到总览。每拍绑定章节卡与一句话说明，共用播放时钟，支持暂停、退出、手动接管；减少动态效果时改为静态分镜列表。

涉及：新增 `src/data/tour.js`、`src/hooks/useTour.js`，复用 `useWorkflow` 时钟。

### 阶段 G：后处理（按实测决定）

Bloom 只作用于发光路径、加轻微暗角，需引入 `@react-three/postprocessing`。先测 1920×1080 的帧时间与显存，若收益不明显或掉帧则不做。

## 三、不做的事

- 不照搬视频右侧的实时数据墙（温度、湿度、流量）：本项目没有真实测点，编造数值与“不宣称未经实测”的既有约定冲突。
- 不做体积光、SSR、景深等 UE 级后处理：目标机是 RTX 4060，收益与成本不匹配。
- 不加整屏滤镜或大面积植被式装饰，不改变浅色工程展陈基调。
- 不改动 11 阶段请求流程、供电与制冷的步骤划分、文案口径与三种展示方式。

## 八、全屏展品布局（2026-11-01）

用户对照参考视频提出：三维场景应铺满屏幕，UI 浮在场景上，而不是"白底三栏 + 中间一张场景卡"。本轮据此重做桌面端外壳，窄屏保持不变。

**做法**

- 断点：仅在 `≥901px` 生效，`≤900px` 继续使用原堆叠布局（手机与平板不受影响）。
- 场景：`.room-shell` 改为 `100dvh` 弹性列，`.scene-card / .viewport-wrap / .viewport` 依次 `position:absolute; inset:0`，画布即为整窗；`body:has(.room-shell)` 禁止页面滚动。
- 浮层：标题块（左上）、系统导航（左侧竖条）、职责说明（右侧 304px 玻璃卡，内部滚动）、底部步骤卡片（36vh 玻璃抽屉）、镜头章节与图层开关（抽屉标题带内的一排胶囊）、视角工具（场景右缘竖排）、展品模式的章节号与玻璃说明卡（右下）。
- 为保证可点击性，章节与图层开关从"浮在场景中"移入抽屉标题带：此前镜头章节浮层挡住了三维投影点，导致"点击文件模块"命中导航条。

**验收期间调整的两处断言（布局变更导致，非迁就实现）**

1. `verify-immersive` "收起说明增加场景空间" → 改为"收起说明隐藏职责面板且画布保持满屏"：画布已是满窗，收起面板不再改变画布尺寸，断言随产品行为更新。
2. `verify-immersive` 的拖拽/滚轮坐标从画布 75%/77% 改到 62%/42%：原坐标在新布局下落在底部抽屉上，拖动不会传给 OrbitControls。

**结果**：`npm.cmd run build` 通过；八组回归 **346/346** 全绿；1440×900 下画布实为 1440×900、文档无滚动（`scrollHeight === innerHeight`）；1024×768 与 375/768 无横向溢出。

**已知限制**

- 900px 高的窗口里，底部卡片高 36vh，当前步骤的"四项事实"仍需在卡片内向下滚动一小段才能看全；1024×768 时镜头章节会换成浮在卡片上方的控制条。
- 浮层会遮挡部分三维区域：被遮住的设备无法直接点选，需先收起面板或旋转视角。

## 九、纯净视野与去滚动（2026-11-01 晚）

用户要求：把所有 UI 收起来，点击才出现，去掉滚动，界面与画面同处一个窗口。

**纯净视野**

- **桌面默认即纯净视野**：`focus` 初值取 `matchMedia('(min-width: 901px)')`，打开页面只见场景与右上角“显示界面”小胶囊。`.focus-mode` 下标题栏、系统栏、说明面板、步骤卡片、章节与图层开关、视角工具、场景说明全部 `display: none`，画布即整窗（1440×900 实测 canvas = 1440×900）。
- **只有“显示界面”胶囊（或 Esc）能把界面唤回**；点击场景不再退出纯净视野（第一版把 `.scene-card` 的 onClick 当作恢复入口，用户明确不要这种行为，已移除）。唤回后顶部的“纯净视野”按钮可再次收起。
- 窄屏（≤900px）不显示“纯净视野”入口，并用 `matchMedia` 变更监听强制把 `focus` 置为 false，避免窗口缩小时界面被隐藏却无入口恢复。
- 场景内的 `.room-callout` 系统标注与贴地文字视为画面内容，纯净视野中保留。

**去滚动（桌面 ≥901px）**

- 底部卡片：由固定 `height: var(--sheet-h)` 改为 `height: auto` + `max-height`（业务 56vh、支撑 72vh），并用 `ResizeObserver` 把实际高度写回 `--sheet-h`，章节与图层胶囊继续贴住卡片上沿。
- 卡片内部改为两列网格。业务模式 `head / steps / stage+devices / strip / note`；支撑模式 `head / tabs / steps / legend+devices / stage / note`；≤1240 宽时支撑改为 `stage` 跨列、`legend` 与 `devices` 同排。步骤条压到单行（业务 11 列、支撑 7 列），事实与设备按钮同步缩小。
- 右侧说明面板与展品浮层改为 `overflow-y: auto` + 隐藏滚动条：正常尺寸下内容刚好放下，极矮视口仍可滚动但看不到滚动条，不裁切内容。
- 面板宽度 304→320（窄桌面 292），减少换行带来的额外高度。

**实测（Playwright 无头 Chrome，三模式 × 分辨率）**

| 视口 | 说明面板 | 步骤卡片 | 结论 |
| --- | --- | --- | --- |
| 1920×1080 / 1600×900 / 1440×900 | 无溢出 | 无溢出 | 一屏内完整可见 |
| 1280×800 | 无溢出 | 无溢出 | 一屏内完整可见 |
| 1366×768 | 无溢出 | 无溢出 | 一屏内完整可见 |
| 1024×768 | 无溢出 | 无溢出（72vh） | 画面剩余高度约 190px，属该尺寸的必然取舍 |

**过程中修掉的问题**

1. 卡片变高后遮住存储模块的三维投影点，`点击实际文件模块可选择节点` 失败。把 11 阶段步骤条改为单行（卡片高度 405→345），恢复点击。
2. 新增按钮改变 Tab 顺序，`verify-present` 原有的“两次 Tab 到达展品开关”失效。改为循环按 Tab 直到焦点进入展品开关，断言语义不变。
3. 支撑卡片初次改网格时漏了 `legend` 区域，图例被自动放置、挤出额外列，内容高度涨到 3590px。补上 `legend` 区域后恢复。

**新增回归（11 项）**：纯净视野入口可见、浮层全部隐藏、画布铺满窗口、页面不滚动、保留显示界面按钮、点击场景不退出、点击显示界面恢复、Esc 恢复、重新加载默认纯净、窄屏自动回到完整界面、375 不显示入口。所有回归脚本在 `goto` 后统一点击一次“显示界面”，因此默认纯净不影响既有断言。

**结果**：`npm.cmd run build` 通过；八组回归 **357/357** 全绿（present 60→71）。
