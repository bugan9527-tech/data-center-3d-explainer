# 关键制作步骤

这个项目拆开只有四块：**一份讲解数据、一个时间源、一个能拆的三维场景、一组断言**。四块按顺序做，每块都有明确的"做完了"标准。下面写的顺序就是实际做出来的顺序，反过来的地方都返工过。

---

## 第 1 步：把讲解压缩成三张表

先不碰三维。用纯数据把"讲什么"写死：

| 表 | 每行写什么 | 本项目的文件 |
| --- | --- | --- |
| 节点表 | id、名称、一句话职责、接收什么、输出什么、和谁配合 | `src/data/systems.js`（8 个系统） |
| 阶段表 | 序号、标题、这一步谁在工作、路径（节点 id 序列）、两句话讲解 | `src/data/requestFlow.js`（11 阶段） |
| 布局表 | 节点 → 世界坐标 + 占用尺寸 | `src/data/roomLayout.js`（9 台机柜） |

**完成标准**：不看图，只读这三个文件，能把原理讲明白。读不通就改文案，别指望模型补救。

这一步决定了后面所有工作量。文案含糊的地方，做模型时一定会卡住。

---

## 第 2 步：先搭灰模，把坐标定死

全部用盒子占位，位置直接来自布局表。此阶段不看材质、不看细节。

- 一次把边界定完：地板尺寸、机柜排布（两排、背靠背、中间热通道）、墙的位置、设备区。
- 本项目的锚点：地板 11.9×8.9、机柜两排 z=0.65／-1.15、母线 y=2.86、CRAC 与 UPS 在 z=-3.65。
- 路径点、机位目标点、标签位置后面全部引用这些数。

**完成标准**：从总览机位能一眼看出"哪排是哪排"。做不到就说明比例不对，这时候改还便宜。

---

## 第 3 步：做相机装置（收益最大，也最容易做错）

相机是这类项目的骨架，不是收尾工作。

- 一个透视相机 + 一张机位表：每个机位给 `position / target / fov / width / height`。
- **不要写死相机距离**。用 `fit = min(视口宽 / width, 视口高 / height)` 反算距离，否则换屏幕就构图崩。
- 切换用缓动（章节 1.2s、特写 0.9s、复位 0.5s），并且必须能被拖动、滚轮、新请求随时中断。
- 减少动态效果时直接定位，不做过渡。

**踩过的坑**：桌面端实际是被 `height` 卡住的，只调 `width` 完全不改构图；只有窄屏（视口比机位更瘦）时 `width` 才生效。改构图必须两个数一起看。

**完成标准**：五种视口尺寸（375／768／1024／1440／矮横屏）下主体都不被裁、不被面板压。

---

## 第 4 步：一个时间源，所有动画从它派生

这是"暂停后画面真的不动"的唯一做法。

- 全局只有一个 `progressRef` + `step`，用 `requestAnimationFrame` 推进；组件里**禁止** `Date.now()`、`performance.now()`、自建 setInterval。
- 暂停 = 不推进；手动选步 = 暂停并回到该步起点；标签页隐藏 = 自动暂停；结束不循环。
- 路径流动、箭头巡游、光点、风扇转速、扫描环，全部读同一个 `progress`。

**完成标准**：暂停，连拍两张画布截图，两张必须逐像素一致。这条不过，后面所有性能与视觉优化都是白做。

---

## 第 5 步：路径与方向

- 路径用穿过节点锚点的曲线（CatmullRom），不用直线拼接。
- 用颜色区分语义：本项目请求蓝／文件数据紫／处理结果绿；供电琥珀／冷风青／回风暖。
- 方向感靠三样叠加，缺一样都会"看不出在动"：曲线上的小箭头（按切线朝向）、沿线移动的光点（相位错开 1/3）、流动虚线。
- 性能红线：同屏 sprite 不超过 40；减少动态效果时不生成光点，只留静态箭头。

**做过才知道**：一开始只放一个发光头，5 秒走完就停，观感是"闪一下"而不是"流动"。改成三个相位错开的头、每条路径都有头（次要路径 0.6 倍大小），才立住。

---

## 第 6 步：拆解

模型侧先满足契约，前端才有得做。

- 每个可拆件是独立节点，命名 `part_*`，**原点在自身几何中心**，否则拉开就歪。
- 前端拉开前先存基准：`node.userData.base = node.position.clone()`，再写 `base + offset`。直接写绝对 z 会覆盖模型自带位置。
- 外壳滑开 + 透明度降到约 0.26；材质必须按实例 `clone()` 并 `dispose()`，因为 `scene.clone()` 共享材质，改一台会让全部一起变透明。
- 只拆主柜（网络→N01、计算→当前选中柜、存储→S01），否则同类第二台外壳滑出去和邻柜重叠。
- 标签按屏幕空间投影并**夹在画布内**；低处部件（PDU 这类 y≈0.45）偏移要压到 0.12–0.15，否则圆点落到地板上。

**完成标准**：拆开后 11 个编号点不互相压；合上后外壳透明度回到 1；同一位置重复点击不会重置机位。

---

## 第 7 步：界面只做两栏

- 左侧（或顶部）状态，右侧说明面板；面板内容全部来自第 1 步的数据，不在组件里写文案。
- 有数字就标"模拟"，底部注明"无实时接口"。这不只是严谨，是这类演示唯一站得住的说法。
- 窄屏改单列堆叠，无横向滚动；键盘能完成主要操作。
- **不要做模式标签**。本项目最早有四个展示模式，后来全部删掉——一条主线 + 可折叠面板，维护成本低一个量级。

---

## 第 8 步：挂诊断属性，写断言

这一步决定项目能不能长期改下去。

- 在画布和面板上挂 `data-*`：`data-camera`（position/target/取景系数）、`data-flow`（step/progress）、`data-support`（章节/步骤/可见性）。
- 回归脚本读这些属性判断状态，**不读像素、不读文案**。文案改一个字就挂的测试，没人愿意维护。
- 字段一旦定下不改名；新增状态就新增字段。

**收益**：本项目界面重做过五次（浅色→深色→HUD→无模式→看板），脚本只换选择器，断言语义一次没改。

---

## 第 9 步：收口

- 一条命令跑完全部回归，输出 JSON + 截图到 `outputs/`。
- 回归按主题拆成多份（本项目 8 份 + 数字孪生专项），每份独立开浏览器，避免一个 WebGL 上下文跑太久崩掉。
- README 只写三件事：怎么跑、有什么、明确不做什么。**检查项数量不写进正文**，只写命令，交付时贴实际输出。

---

## 十个"踩过才知道"

| 现象 | 真正的原因 | 处理 |
| --- | --- | --- |
| 改机位 width 构图没变 | 取景被 height 卡住 | 两个数一起看，别只调一个 |
| 改一台机柜透明度，全部变透明 | `scene.clone()` 共享材质 | 按实例 clone + dispose |
| 拆开的部件位置全歪 | 模型原点在柜体中心 | 导出前把原点移到几何中心 |
| 暂停后画面还在轻微动 | 组件自己读了时间 | 全部改读同一个 progress |
| 页面闲着也满载 | 每帧都在跑 | 静止按需渲染（invalidate） |
| 地板边缘一条硬线 | 几何切边 | 用世界坐标径向淡出贴图，别加边框几何 |
| 新设备放不下 | 先在布局上排 U 位 | 改"填空档"，别动既有锚点（锚点是写死的世界坐标） |
| 标签跑到画布外 | 标签位置没有夹取 | 屏幕投影后夹进画布留 16px |
| 回归一改文案就挂 | 断言读了文本 | 改成读 `data-*` |
| 文档和实现打架 | 两个窗口并行、口径没统一 | 口径变更当轮就回写 README |
