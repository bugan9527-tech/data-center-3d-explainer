# 批次 D 实施记录：备份与容灾

状态：**已完成**。新增第八个系统“备份与容灾”和一台独立备份机柜 B01。

## 一、为什么单独做一台机柜

需求书写的是“在存储区域增加备份服务器、独立备份存储设备、可选磁带库”，并明确“区分主存储与备份存储，不要把本地备份直接等同于异地容灾”。

如果要满足“独立”，备份设备就不能塞进 S01／S02 —— 那正是“本地备份和主存储放在一起”的错误示范。所以做了一台独立机柜 `B01`，位置在后排、`x = 2.1`、`z = -1.15`，与前排主存储柜 S01 前后相对。

候选位置只有后排两个空位（`x = 2.1` 与 `3.55`），因为：

- 前排五列已满（`-3.65 / -1.65 / -.3 / 2.1 / 3.55`）；
- 再往右放（`x = 4.55`）会超出配电母线末端 `x = 4.2`，`Busway` 会给每台机柜生成一个抽头方块，落在母线上就会出现一个悬空的抽头；
- 地板不透明核心区是 `|x| ≤ 5.1`，右侧道具带 `x 4.2–4.7 / z 1.7–3.1` 也被占用。

## 二、机柜构成（5 个可拆解部件）

新建 `blender/source/generate_equipment.py` 的 `backup` 分支，与 network／storage 共用同一套柜体、材质和 `part_*` 契约。

| 部件 | 位置（Blender z） | 形态 |
| --- | --- | --- |
| `part_backup_server_01` | 1.96 | 2U，3 个硬盘位 + 状态灯 + 服务口 |
| `part_backup_server_02` | 1.70 | 同 01，并可接管 |
| `part_tape_library` | 1.15（0.62 高） | 2 × 8 磁带槽 + 操作面板 + 投带口 |

| `part_backup_shelf_02` | 0.34 | 同上 |

磁带库刻意做了 **16 个青色磁带手柄**——这是它与主存储柜最明显的形态差异，否则两台深色机柜摆在同一个角落根本分不出来。

## 三、机位：为什么不是正面

B01 在后排且 `rotation: π`（与后排其余机柜一致，正面朝向 −z 的冷通道）。这带来一个直接后果：**正面朝着后墙**，而机柜正面到后墙只有 3.7 m，中间还立着两台 CRAC。

- 从 +z 侧拍：只能看到机柜背面。
- 从 −z 侧正面拍：相机要退到 `z ≈ -5.5`，跑到后墙（`z = -4.83`）外面，视线被墙挡住。
- 从正上方俯拍：桥架就在 `y 2.66`、母线 `y 2.86`，全遮。

最后用了**后左三分之四视角**：`position [-.8, 2.55, -3.9]`、`target [2.1, 1.2, -1.3]`、`width 3.4 × height 2.8`、`fov 36`。按 `frameDistance()` 解出的实际机位是 `[-0.93, 2.61, -4.02]`——在墙内侧，斜看机柜正面。

顺带一个好处：后排机柜的部件沿局部 +z 拉出，经 `π` 旋转后是世界 −z，正好朝相机方向，拆解不会往墙里钻。

## 四、与主存储怎么区分

- **空间**：B01 在后排、S01／S02 在前排，中间隔一条热通道。
- **形态**：磁带库的槽位阵列、备份服务器的双机配置，与主存储的控制器 + 磁盘架不同。
- **文案**：系统说明写明“备份要能顶用，前提是与主存储分开存放；本地备份也不等于异地容灾”，部件职责里磁带库写的是“便于长期留存与异地转移”。
- **不做**：没有备份窗口、去重、异地复制的模拟，也没有备份任务进度条。

## 七、已知局限

**B01 在总览里被前排存储柜和 `z = -1.15` 的桥架挡住上半部分**，只能看到机柜顶部一段。它没有位置可选——后排任何位置都会被前排同列机柜挡住，这是双排背靠背布局的必然结果（C03／C04 同样如此）。缓解手段是它的系统标注和拆解视图：点标注即进入特写，5 个部件都能看全。

**顺带记录一个环境问题**：跑回归时如果同时留着多个 playwright 会话，浏览器可能在 teardown 阶段直接退出（报 `Target page, context or browser has been closed`）。这不是代码问题，关掉遗留会话后八组全过。
